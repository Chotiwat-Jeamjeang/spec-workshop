  <name>Task 1: Package-legitimacy gate — verify lighthouse before any third-party code runs</name>
  <what-built>
Nothing has been installed. This gate precedes the first execution of third-party code.

`01-RESEARCH.md`'s Package Legitimacy Audit returned a **`[SUS]` ("too-new")** verdict for `lighthouse`, the tool this plan uses to measure FCP. The audit's own assessment is that this is very likely a false positive *about the package's identity*: `lighthouse` was first published in 2012 (~14 years old), is maintained under Google's official `GoogleChrome` GitHub organisation, and has ~3.8M weekly downloads. The flag is almost certainly tripping on the recency of the latest published version (`13.4.1`, published 2026-07-20), which is normal cadence for an actively shipped tool.

That assessment is the audit tool's verdict reported honestly, not an override of it — and `npx lighthouse` still downloads and executes code. Per protocol, a `[SUS]` package cannot be run without a human confirming its legitimacy first, and this gate is never auto-approved regardless of `auto_advance` or yolo mode.

The plan uses `npx lighthouse` ephemerally rather than adding it as a `devDependency`, so nothing is written to `package.json` and nothing persists in the project's dependency tree.
  </what-built>
  <how-to-verify>
Confirm the package is the genuine Google tool before it is executed:
1. Open https://www.npmjs.com/package/lighthouse and confirm the repository link points at `github.com/GoogleChrome/lighthouse`.
2. Confirm the weekly download count is in the millions, not the hundreds, and that the package is not marked deprecated.
3. Confirm the publisher/maintainer list is the Google Chrome team, not an unfamiliar single account.
4. Confirm the latest version shown matches or is newer than `13.4.1` and that its publish date looks like ordinary release cadence rather than a package resurrected after years of dormancy.
  </how-to-verify>
  <resume-signal>Type "approved" to allow the ephemeral `npx lighthouse` invocation, or "denied" to skip the scripted measurement — in which case Task 2 falls back entirely to the manual DevTools measurement described in its human-check.</resume-signal>
