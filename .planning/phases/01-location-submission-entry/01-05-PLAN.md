## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-16 | Tampering (script injection) | note content reflected into the counter element | high | mitigate | The counter writes only a computed number and fixed Thai copy, never the note content itself, and assigns through `textContent` rather than `innerHTML`, so nothing the user types is ever parsed as markup. |
| T-01-17 | Tampering | client-side toggle used to bypass the QR trust decision | medium | mitigate | The toggle only reveals a picker whose options come from the server's registry; switching to it does not upgrade an unsigned request into a signed one. Plan 01-06's server-side validation re-derives trust from the submitted values and never from the client's `data-mode`. |
| T-01-03 | Tampering (script injection) | note label, counter and control text interpolation | high | mitigate | All new template content is static Thai copy; any interpolated value continues to use EJS's escaping output tag. |
| T-01-18 | Denial of Service (client) | unbounded note input | low | mitigate | Native `maxlength="500"` physically caps input in the browser; plan 01-06 adds the server-side re-check for clients that bypass the browser entirely. |
</threat_model>
