  <action>
Create `scripts/generate-qr.js` as a CommonJS ops CLI run with `node scripts/generate-qr.js`. It must not be an HTTP route, and no route may invoke it: SPEC frames QR registration as a future admin-UI concern and `01-CONTEXT.md` puts an admin UI out of scope for this phase, so a CLI satisfies the need without building or securing a new endpoint.

The script loads `dotenv` so it picks up `QR_SIGNING_SECRET` from `.env` the same way the app does, reads the registry through `src/services/locationStore.js`'s `getAll()` rather than re-implementing the file read (so the BOM-strip and the path resolution stay in one place), and resolves its output directory as `qr-output/` at the repository root via `path.join(__dirname, '..', 'qr-output')`, creating it recursively if absent.

For each registered location it computes `sig = signLocationId(loc.location_id)` and builds the URL `${BASE_URL}/report?location_id=${encodeURIComponent(loc.location_id)}&sig=${sig}`, where `BASE_URL` is `process.env.QR_BASE_URL` falling back to `http://localhost:3000`. Percent-encoding the id matters: `DORM-1` is safe today, but D-03 hands this file to a non-developer who may introduce ids needing encoding, and the encoded form is what must round-trip.

It writes the PNG with `QRCode.toFile(path.join(outDir, loc.location_id + '.png'), url, { errorCorrectionLevel: 'H', width: 400, margin: 2 })`, awaited (the library returns a promise when the callback is omitted). Error-correction level H recovers roughly 30% of a damaged symbol, which is the right choice for outdoor, high-wear campus signage exposed to rain, scuffing and sticker peel. It then prints one line per location giving the id, the output path and the URL, and exits non-zero with a readable message if the registry is empty or if any write fails.

Add `qr-output/` to `.gitignore` — generated images are build output, and committing them would also freeze a snapshot of signed URLs into version history. Keep the three existing entries untouched.

Append `QR_BASE_URL=` to `.env.example` below `QR_SIGNING_SECRET=`, with a one-line comment noting that it is optional and defaults to `http://localhost:3000`.

Do not add any route, middleware, or export that lets a request trigger generation, and do not write the signing secret or any derived key material into the output directory or the console.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `QR_SIGNING_SECRET` → minted QR URLs | The script holds the signing key in memory; the URLs it emits are the only thing that should ever leave it. |
| `qr-output/` → physical world | Generated PNGs become printed stickers installed in public space; anything encoded in them is permanently readable by anyone. |
| `config/locations.json` → script input | Hand-edited by a non-developer per D-03; ids may contain characters needing URL encoding. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-06 | Information Disclosure | signing secret in the generation path | high | mitigate | The script reads `QR_SIGNING_SECRET` from the gitignored `.env` and never prints, writes or encodes it — only the derived per-location HMAC leaves the process. Asserted by the source check that no key material is logged. |
| T-01-14 | Information Disclosure | committed QR artifacts | medium | mitigate | `qr-output/` is gitignored, so signed URLs are never frozen into version history where a later repository leak would expose a full set of valid signatures. |
| T-01-15 | Elevation of Privilege | QR generation exposed as a route | high | mitigate | Generation is a CLI with no Express import and no router; a source assertion fails the task if any HTTP surface appears. An unauthenticated mint endpoint would let anyone forge a valid QR for any id, defeating the entire signature scheme. |
| T-01-02 | Tampering | signature reuse across locations | high | mitigate | The round-trip test asserts, for every ordered pair of distinct locations, that one location's signature does not validate another. |
| T-01-07 | Denial of Service (availability) | malformed registry input to the script | low | mitigate | The script reads through `locationStore.getAll()`, inheriting the BOM strip and the loud, path-naming parse failure, and exits non-zero with a readable message on an empty registry. |
</threat_model>
