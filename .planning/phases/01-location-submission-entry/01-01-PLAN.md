**`src/services/qrSignature.js`** — pure utility, no Express import, mirroring `imageType.js`'s guard-first shape. Export `signLocationId(locationId)` and `verifyLocationSignature(locationId, providedSig)`. `signLocationId` computes `crypto.createHmac('sha256', secret).update(locationId).digest('hex')` and returns the first 32 characters. `verifyLocationSignature` guards first and returns `false` (never throws) when `providedSig` is not a string or its length is not exactly 32; only then does it decode both sides with `Buffer.from(…, 'hex')`, re-check that both buffers have equal length, and compare with `crypto.timingSafeEqual`. Both guards are load-bearing and neither is redundant: `Buffer.from(str,'hex')` silently truncates malformed hex instead of throwing (so a `try/catch` catches nothing), and `crypto.timingSafeEqual` throws `RangeError` (`ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH`) on unequal buffer lengths. Never compare signatures with the string equality operator.

Read the secret through a small internal accessor called at call time, not at module load, and have it throw `Error('QR_SIGNING_SECRET is not set — see .env.example')` when the value is missing or empty. Call-time reading is deliberate: it makes `require()` order irrelevant for tests while keeping the failure loud and named. (This is a considered divergence from the module-load-time read shown in `01-RESEARCH.md` Pattern 1.)
