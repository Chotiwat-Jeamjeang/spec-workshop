# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-authored EJS + vanilla CSS + vanilla JS |
| Icon library | none — hand-authored inline SVG only (lock, checkmark, warning icons), no icon font/library |
| Font | System font stack (no external web font) |

**Rationale (judgment call, no upstream artifact locked this):** This project is explicitly plain HTML/CSS/JS with no framework and no bundler (`.claude/CLAUDE.md` "What NOT to Use": no React/Vue/Svelte, no Vite/webpack/Rollup) and is server-rendered via EJS (01-RESEARCH.md Pattern 2). The shadcn initialization gate applies only to React/Next.js/Vite projects — not applicable here, so it was skipped rather than asked. `components.json`/`tailwind.config.*`/`postcss.config.*` were confirmed absent from the repo root this session.

**Font declaration (from 01-RESEARCH.md Common Pitfall #6, adopted as-is):**
```css
font-family: system-ui, -apple-system, "Segoe UI", "Leelawadee UI", "Noto Sans Thai", sans-serif;
```
Zero extra network requests — critical for the FCP ≤2s/4G budget (SUBM-04). Do not add a Google Font or any `@font-face` for this phase.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (e.g. lock icon next to locked-location label) |
| sm | 8px | Compact spacing — label-to-input gap, note counter margin |
| md | 16px | Default element spacing — between form fields, card internal padding on mobile |
| lg | 24px | Section padding — form card padding at ≥768px, spacing above/below the location block |
| xl | 32px | Layout gaps — page top/bottom margin at ≥768px |
| 2xl | 48px | Major section breaks — not used within this single-section form; reserved |
| 3xl | 64px | Page-level spacing — not used within this single-section form; reserved |

Exceptions:
- **44px minimum touch target height** for the `<select>` trigger, "ถัดไป" (Next) button, and the "ไม่ใช่จุดนี้" control on all breakpoints — this is below the 8pt base scale but required per WCAG 2.5.5 target-size guidance for a mobile-first, no-login public form used one-handed at a bin location.

## Responsive Behavior (SUBM-04)

Not a template-standard section — added because SUBM-04 (FCP ≤2s/4G, correct rendering at 375/768/1024px) is this phase's fourth requirement and needs a concrete layout contract, not just spacing tokens.

| Breakpoint | Layout |
|------------|--------|
| 375px (mobile, default/no media query) | Single-column, full-width form with 16px side padding. No max-width constraint. This is the primary target — most scans happen on a phone at the bin. |
| 768px (tablet) | Form container gets `max-width: 480px`, centered (`margin-inline: auto`), 24px card padding. Prevents the `<select>`/textarea from stretching uncomfortably wide. |
| 1024px (desktop) | Same 480px max-width, centered; increase page vertical margin to 32px (xl token). No multi-column layout — this is a single short form, a second column would add complexity with no benefit. |

CSS approach: mobile-first (`min-width` media queries only), no CSS framework, no JS-driven layout. Media query breakpoints: `@media (min-width: 768px)` and `@media (min-width: 1024px)`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 400 (regular) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | N/A — not used this phase | — | — |

Exactly 3 declared sizes (14/16/20) and 2 declared weights (400/600) — no fourth size or third weight needed for a single short form. Display is unused: this phase has no hero/marketing copy, only a page title (Heading) and body content.

**Role assignments:**
- **Body (16px/400/1.5):** input/textarea values, note content, dropdown option text, error banner message text.
- **Label (14px/400/1.4):** form field labels ("รายละเอียดเพิ่มเติม (ไม่บังคับ)"), the note character counter, helper/microcopy.
- **Heading (20px/600/1.2):** page title ("แจ้งจุดขยะ"), the confirmed location name when in locked (QR-verified) state — the weight bump is part of what visually distinguishes the locked state from the dropdown state (see Color below).
- **CTA/button text:** 16px (Body size) at 600 (Heading's weight) — reuses the two already-declared tokens, does not introduce a third size or weight.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background |
| Secondary (30%) | `#F1F5F9` | Form card background, dropdown/select surface, note textarea background |
| Accent (10%) | `#16A34A` | See "Accent reserved for" below |
| Destructive | `#DC2626` | Error/failure states only |

**Accent (`#16A34A`, green-600) reserved for — explicit list, nothing else:**
1. The QR-locked location box: 4px left border + a small badge/icon ("ยืนยันจาก QR" — see Copywriting) — this is the primary visual signal that distinguishes the **locked** state from the **dropdown** state (D-07/D-08's shared field area must otherwise look identical apart from this treatment).
2. Focus outline ring on all interactive elements (`<select>`, `<textarea>`, buttons) — one consistent focus color across the form.
3. The "ถัดไป" (Next) primary CTA button background.

**Destructive (`#DC2626`, red-600) reserved for — error states only, never used decoratively:**
1. Invalid/unregistered QR error banner (border + icon + text) — SUBM-02.
2. Defense-in-depth note-length-exceeded message (rare — `maxlength="500"` physically blocks this client-side; only reachable via the validate-endpoint round trip).
3. Network/validate-request failure banner (see UI Considerations).

**How the locked vs. dropdown states are visually distinguished (required by the run's brief):**
| State | Container | Border | Icon/Badge | Field control |
|-------|-----------|--------|------------|----------------|
| **Locked** (valid QR) | Secondary surface (`#F1F5F9`) | 4px solid Accent left border | Lock/checkmark SVG (Accent) + "ยืนยันจาก QR" label, Heading-weight location name | Read-only text, not a form control; "ไม่ใช่จุดนี้" text-link below it |
| **Dropdown** (direct entry, or after "ไม่ใช่จุดนี้") | Secondary surface (`#F1F5F9`) | 1px solid neutral gray (`#CBD5E1`) — no accent border | None | Native `<select>` with a disabled placeholder first option |

Same DOM position and same outer spacing (per D-07) — only the border color/weight, badge presence, and control type differ, so the two states are unmistakable at a glance without changing the form's overall rhythm.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5). Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy.

**Elements classified:**
- Location field (locked/dropdown/error) — kind: `form`
- Location dropdown options — kind: `list-collection`
- Note field — kind: `form`
- "ถัดไป" (Next) CTA / validate action — kind: `interactive-control`
- "ไม่ใช่จุดนี้" control — kind: `interactive-control`

Applicable state considerations resolved: 9 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | location dropdown (list-collection) | ✅ covered | If `config/locations.json` resolves to zero entries, the dropdown renders disabled with the Empty-state copy (see Copywriting Contract) and the "ถัดไป" CTA stays disabled — references Copywriting Contract "Empty state heading/body" rows. |
| empty | location field, note field (form) | ✅ covered | Initial page render (no data entered) is the normal happy path, not a degraded state: dropdown/locked block per entry path, note textarea empty with "0 / 500 ตัวอักษร" counter, no error banner shown. |
| loading | "ถัดไป" CTA (interactive-control) | ✅ covered | Button switches to disabled + "กำลังตรวจสอบ..." label while `POST /api/waste-reports/validate` is in flight (Copywriting Contract → Additional copy reference). No loading state exists for the location/dropdown data itself — it is SSR-rendered in the initial HTML response (01-RESEARCH.md Pattern 2), never fetched client-side. |
| error | location field (form) | ✅ covered | Invalid/unregistered QR → single generic error banner (Destructive color) + fallback link to the dropdown — Copywriting Contract "Error state" row, Color → Destructive. |
| error | "ถัดไป" CTA / validate action (interactive-control) | 🧪 backstop | Network/server failure on the validate POST shows the "Validate-request network/server failure" banner without discarding entered form state. Flagged as backstop (not visually inspectable at plan time) because it depends on the actual fetch/error-handling code path — verify at execution time with a wired test (e.g., mock a 500/timeout response) rather than a visual-only check. |
| populated | location dropdown (list-collection) | ✅ covered | Happy path: dropdown lists all registered location `name` values (D-06: name only, no lat/lng), in `config/locations.json` order, below the disabled placeholder option. |
| partial | location field (form) | ✅ covered | Native `<select>`'s first option is a disabled placeholder ("เลือกจุดที่แจ้ง") forcing an explicit choice; attempting to proceed with the placeholder still selected shows the "Required-field inline error" copy inline, CTA does not proceed. |
| overflow | location field — locked display & dropdown options (form, list-collection) | ✅ covered | Locked-state location name wraps to a second line (no truncation) rather than clipping — expected campus location names are short, and D-03's placeholders will be replaced later without a code change to this rule. Dropdown `<option>` text relies on native browser rendering/truncation; no custom CSS truncation is applied. |
| zero-one-many | location dropdown (list-collection) | ✅ covered | Dropdown layout is unaffected by location count — natively scales from the zero-item empty state through the seeded 5 (D-04) to any future N with no layout change required. |
| long-text | note field (form) | ✅ covered | `<textarea>` is a fixed-height, roughly 4–5 visible rows, `resize: vertical` allowed, with native internal scroll for content exceeding the visible area — chosen over auto-grow to keep the page layout/height stable on small screens (375px) as the user types. |
